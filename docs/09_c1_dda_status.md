# C1 —— 加载器采样改成小数（DDA）：进度与下一步

## 为什么要改

`wall_tf_load.v` 把 BMP 降到 192×144 用的是**整除步长**：

```verilog
sx <= dv_q[15:0];   // dv_q = img_w / 192
sy <= dv_q[15:0];   // dv_q = img_h / 144
```

列采样是"每 sx 个源像素取一个"。对卡里的 640×480 图：`sx = 3`、`sy = 3`，
实际只取了 `192×3 = 576` 列、`144×3 = 432` 行 —— **右边 64 列、下面 48 行从来没被
采样过**，这就是"照片右边和下面少一部分"的根因（不是窗口、不是缩放）。

`tb_tf_load` 一直 PASS 是因为它的 CAM1/CAM3 测试图本来就是 192×144（步长 1），
而 CAM2/CAM4 是 384×288（步长 2）——旧模型也照着整除写，等于把 bug 一起"验证"了。

## 昨晚做过的（已回退，代码在下面）

DDA（小数累加）方案：

- 列：`acc += 192; hit = acc >= img_w; hit 时取样并 acc -= img_w`，每行起始
  `acc = max(0, img_w-192)`，保证第一个像素必然被采到；
- 行：同理 `racc += 144`，`racc_hit` 决定这一源行是否保留；
- `col_acc` 扩到 17 位；`m_first = min(img_h,144)-1`（bottom-up 从最高的 bank 行
  开始倒数）。

**实测结果**（vsim，`tb_tf_load`，模型已同步改成 DDA）：

| 版本 | 不匹配字 |
|---|---|
| 旧（整除） | 0（但模型也是整除，等于没测出来） |
| DDA v1 | 31,488 / 110,592 |
| DDA v2（模型与 RTL 对齐列采样后） | **22,656 / 110,592** |

第一个不匹配点：`bank 1, row 3, col 0`：`got=0x03F`、`want=0x020`。测试图是
`b = ((x//8 + y//8) & 1)*255` 的棋盘，所以

- `got` 的 b=31 → `b=255` → `y//8` 为偶 → **y ∈ 0..7**
- `want` 的 b=0 → **y = 7**

→ **行方向还差 ~4 个"保留行"**（bank row 3 拿到的是 y≈8..15 的源行）。列方向已经对齐。

## 下一步（预计 1~2 h）

1. 查 `emit_row` / `brow` / `bottom-up` 三者的时序：第一保留行应当落在 bank row
   143（`m_first`），之后每个保留行 −1。差 4 行说明 初始 `racc` 或"保留判定比写入
   晚一拍"这两处之一还差一个相位。
2. 用 `tb_tf_load` 反复迭代（现在它包含 2:1 的 CAM2/CAM4，能真正验证覆盖）。
3. 通过后：`build.ps1 -Role both`、`tools/flash_pair.ps1`，然后肉眼确认
   **照片右下角（台阶/右柱）回来了**。

## 注意

- 回退后 RTL 与 `tb/*.hex` 都是"整除"版本且 `tb_tf_load` PASS（工作区干净）；
- `tools/make_tb_fat32.py` 的期望模型也已还原；改 DDA 时要**同时**改它，
  否则 TB 会把新行为判成错；
- 采样模型里的 `pixel(x, y, w, h)` 用的是**顶向左下**坐标（y=0 是图顶），
  而 RTL 走的是 BMP 文件行序（bottom-up，文件第 0 行 = y = h-1），换算别搞反。

## 已完成（2026-10-31 03:0x）

DDA 采样已通过 `tb_tf_load`：**0 / 110,592 字不匹配**。

关键修正（就一处）：**`racc` 初值必须是 0，不能是 `img_h-144`**。

原因：列检查和行检查的**相位不同**
- 列：`col_hit` 在"写当前像素之前"判定 → 初值 `max(0, img_w-192)`，保证第一个像素必被采到；
- 行：`racc_hit` 在"行末"判定，决定的是**下一行** → 初值 0 才能让第 2 行的判定先触发；
  而第 0 行由 `sel_first = 1` 无条件保留。

用 `img_h-144` 会让每一行都被保留（brow 每行都减 1），表现为"垂直方向只采到图的一半、
而且每行重复两次"。

调试手段（已留在 TB 里，`+TRACE` 打开）：每条写事务打印 `n bank brow k px emit_row`，
一眼就能看出 `brow` 是"每行减 1"还是"每保留行减 1"。第一次做 DDA 时如果不 dump 这个，
很容易误判成列方向的问题。

模型侧同步改了 `tools/make_tb_fat32.py`（行序：BMP 文件第 i 行 = `y = h-1-i`；
保留行集合按上面的相位生成；bank 行号 = `n_kept-1-idx`）。
