# 方案 3 · 跨屏窗口拖拽的监控墙 —— 接口与协议规范 v0.1

> 本文件是**冻结接口**，RTL、仿真、验收都以它为准。
> 改动任何字段必须先改这里，再改 `rtl/`，再跑 `tb/`。

## 1. 产品与演示

两块 HX4S20C（EG4S20BG256），各接一块 640×480 HDMI 屏，并排拼成一个 **1280×480 的"桌面"**。
桌面上有 4 个监控窗口（PiP），操作员用板载按键把任意窗口从 A 屏拖到 B 屏。

30 秒演示脚本：

```
① 两屏显示同一张桌面：网格背景 + 4 个窗口（2 个在 A，2 个在 B，1 个正好跨接缝）
② 按 KEY1 循环选中窗口，选中窗口出现白色高亮边框
③ 按 KEY2 进入拖拽，KEY3/KEY4 左右移动（1 px/帧）
④ 窗口跨接缝时，接缝两侧像素严丝合缝（同一份全局坐标、同一个窗口表快照）
⑤ 窗口中心越过 x=640 后松手 → 面板 OWN 由 A 变 B，B 板的按键继续拖这个窗口
⑥ 拔掉排线：两屏各画各的，窗口冻结在最后位置，HUD 显示 LINK LOST
⑦ 插回排线：≤3 帧内恢复，窗口位置接续
```

## 2. 坐标与世界

| 量 | 值 | 说明 |
|---|---|---|
| 单屏分辨率 | 640×480 @60Hz，25 MHz 像素时钟 | 复用 P1-05A 时序（800×525 总时序） |
| 世界尺寸 | `WORLD_W=1280`，`WORLD_H=480` | 屏幕并排，A 在左 |
| A 屏区间 | `x ∈ [0, 640)` | 节点 A（`NODE_ID=0`） |
| B 屏区间 | `x ∈ [640, 1280)` | 节点 B（`NODE_ID=1`） |
| 窗口坐标 | **全局坐标**，永远不转局部坐标 | 局部绘制时再减 `NODE_X0` |
| 坐标精度 | 整数像素（1 px = 1 单位） | 第一版不做亚像素 |

**铁律 1：窗口位置只存全局坐标。** 渲染时用 `local_x = gx - NODE_X0` 求交，绝不先转局部坐标再存。

**铁律 2：桌面背景必须是 `(x,y)` 的纯函数**，两节点用同一份逻辑，接缝处才不会出现色差/错行。

## 3. 窗口表（4 个窗口）

窗口表 = 4 条 64-bit 记录，按 `win_id = 0..3` 固定顺序。

### 3.1 单窗口记录（64 bit）

| 位域 | 字段 | 宽度 | 含义 |
|---|---|---|---|
| `[11:0]` | `gx` | 12 | 全局左上角 x，0..1279（允许负值出屏？第一版不允许） |
| `[23:12]` | `gy` | 12 | 全局左上角 y，0..479 |
| `[33:24]` | `w` | 10 | 窗口宽，40..640 |
| `[43:34]` | `h` | 10 | 窗口高，40..480 |
| `[47:44]` | `src` | 4 | 内容源编号（0..3 = 内置图案，8..15 预留给 SDRAM 图库） |
| `[49:48]` | `z` | 2 | 层序，0 最底，3 最上 |
| `[50]` | `owner` | 1 | 0=A 控制，1=B 控制（决定边框颜色与按键归属） |
| `[53:51]` | `flags` | 3 | `[51]` selected，`[52]` dragging，`[53]` frozen（链路断） |
| `[57:54]` | `win_id` | 4 | 固定 = 索引，用于自检 |
| `[63:61]` | `rsv` | 3 | 全 0 |
| `[60:59]` | `pic_idx` | 2 | **相册页码**（C9）：`frameless` 窗口显示哪一张 1:1 拷贝，0..3 = CAM1..CAM4。其余记录由 `wall_input` 写入时高 6 位恒 0，所以只有相册时序器会置这两位 |
| `[58]` | `frameless` | 1 | 1 = 整幅全屏窗口（相册模式），内容取 SDRAM 里 `HI_BASE + pic_idx*307200` 的 640×480 1:1 拷贝 |

> 位序约定：LSB 在前，链路按**低字节先发**。
>
> C9 之前 `[63:58]` 是整个 6 bit 的 `rsv`（当时只有 bit58 被 `frameless` 用掉）。
> `pic_idx` 落在 `rsv` 里是**有意的**：窗口记录、STATE 帧格式、B 板跟随逻辑
> 都不用改一个字节 —— 表每帧整份广播，B 自动看到新页码。

### 3.2 默认布局（上电）

| id | src | gx | gy | w | h | z | owner |
|---|---|---|---|---|---|---|---|
| 0 | 0 彩条 | 40 | 40 | 320 | 240 | 0 | A |
| 1 | 1 棋盘 | 360 | 80 | 320 | 240 | 1 | A |
| 2 | 2 渐变 | **600** | 120 | 320 | 240 | 2 | A |
| 3 | 3 十字 | 940 | 60 | 320 | 240 | 3 | B |

窗口 2 的 `600..920` 横跨接缝 `640`，**上电第一帧就是跨接缝状态**，答辩时不用现场拖也能展示。

## 4. 链路

### 4.1 物理层（复用 murmur_d1 已验证的 4-bit 同步链路）

| 信号 | 方向 | J1 脚 | FPGA 球 | 说明 |
|---|---|---|---|---|
| `link_clk` | A→B | 9 | K12 | 6.25 MHz，A 生成（50 MHz / 8） |
| `link_sync` | A→B | 21 | — | 60 Hz 帧同步脉冲，宽 1 个 link_clk |
| `link_vld` | A→B | 7 | J14 | 本拍 `link_d` 有效 |
| `link_d[3:0]` | A→B | 1,2,3,5 | D14,G11,G12,H13 | 数据，A 在 link_clk 上升沿后稳定 |
| `link_bvld` | B→A | 15 | — | B 的返回有效 |
| `link_bd[3:0]` | B→A | 13,17,19,2 | — | B 的返回数据 |
| GND | — | 12,30 | — | 至少两根 |

> 具体球位在 `pin/*.adc` 里定稿；上表沿用 murmur_d1 的 J1 分配，**改脚必须两板同时改**。

### 4.2 帧格式（nibble 流）

每个 `link_clk` 传 1 个 nibble。帧结构：

```
0xA   0x5   TYPE   LEN   payload[0..LEN-1]   CRC8
```

- `TYPE` ∈ {1=STATE, 2=INPUT, 3=HB}
- `LEN` = 负载字节数（≤ 40）
- `CRC8` = poly `0x07`，初值 `0x00`，覆盖 `TYPE,LEN,payload`
- 接收端：连续两个 nibble 命中 `0xA`,`0x5` 才开始收帧；CRC 错 → 丢帧并 `err_cnt++`，重新同步

### 4.3 报文

| TYPE | 方向 | LEN | 负载 |
|---|---|---|---|
| 1 `STATE` | A→B | 40 | 见 4.3.1（字节 0..4 状态 + 字节 5..36 窗口表 + 37..39 亮度/对比度） |
| 2 `INPUT` | B→A | 3 | `key_state`(1B: 低 4 位 = KEY1..4，按下为 1) + `key_edge`(1B) + `seq`(1B) |
| 3 `HB` | 双向 | 4 | `frame_cnt`(2B 低先) + `status`(1B: bit0 link_ok, bit1 table_valid, bit2 degraded) + `rsv`(1B) |

#### 4.3.1 STATE 负载（40 B：W3 扩到 37，W3.5 扩到 40 —— 已经是接收端上限）

| 字节 | 内容 |
|---|---|
| 0 | `seq` = A 的 `frame_cnt[7:0]`（B 用来取闪烁相位） |
| 1 | `{audio level[2:0], anim[4:0]}` |
| 2 | `{car_cyc[1:0], music_ok, mode[2:0], sel[1:0]}` |
| 3 | `fade_gain[7:0]`（255 = 满亮度；轮播淡入淡出由 A 算，B 直接照用） |
| 4 | `{mp8, t_tlvl[4:0], adj_on, car_auto}`（C5 的过渡调光 5 bit；C10 把最高位给了字幕相位 `frame_cnt[8]`） |
| 5..36 | 4×8 B 窗口记录（id 0..3，低字节先发） |
| 37 | `brightness[7:0]`（0x80 = 中性） |
| 38 | `contrast[7:0]`（1.7 定标，0x80 = 1.0） |
| 39 | `{3'b0, t_marq, t_mute, t_osd, pic_id[1:0]}` = 37/38 属于哪张图 + C6 的静音/UI 显隐 + C10 的底部字幕开关 |

- 37..39 是**轮播广播**：一帧带一张图，4 帧（~67 ms）覆盖 4 张，B 写进自己的 4 项表
- **C10 底部滚动字幕**：滚动相位 = `{byte4[7], byte0[7:0]}` = A 的 `frame_cnt[8:0]`（512 px 一个周期）。两板**必须**用同一个相位值，否则 16 px 的字在接缝处会被撕开半个字；开关 = byte39 bit4。两位都是**已有字节里的空位**，所以负载长度没变
- `STATE` 每帧发一次：40+4 = 44 B = 88 nibble ≈ **14.1 µs @6.25 MHz**（仍在行消隐内）
- 接收端 `payload` 是 40 字节，**没有余量了**：再加字段必须先扩 bank（320→384 bit）
- **两块板的 bitstream 必须同一版**：负载布局一改（W3 35→37，W3.5 37→40），旧 B 解新 A 的表会错位

### 4.4 单写者规则（防止两节点同时改表）

**A 是窗口表的唯一写者。**

- B 只做两件事：把自己的按键状态发上去、把收到的 `STATE` 显示出来
- 任何"谁在拖这个窗口"只是表里的 `owner` 字段，不是写权限
- 这保证同一时刻只有一个节点能改 `gx`，不会出现两个节点各改一半导致抖动

> 这是"单写者"最简单也最可靠的实现：**表只有一份权威副本，在 A 上**。
> 真正的写者转移（token ring）留作后续，先保证行为正确。

## 5. 渲染流水线

```
        ┌────────────── 25 MHz pixel domain ───────────────┐
clk50 → PLL ─→ wall_raster (640x480 raster, x/y/de/sof)    │
                  │                                        │
窗口表快照 ───────→ wall_scene  (桌面 + 4 窗口 + HUD)        │
                  │  rgb[23:0]                             │
                  └→ apug092_tx_wrapper → HDMI PHY → 屏     │
```

- **不做帧缓存**：每个像素组合逻辑现算（桌面/窗口都是 `(x,y)` 的函数）
- 因此**没有撕裂、没有双缓冲延迟**，接缝一致性由"同一份表快照 + 同一个 `(x,y)` 函数"天然保证
- 每像素开销：4 路窗口区间比较 + 被选中窗口的图案生成 + HUD 覆盖 ≈ 组合逻辑 ~6 级

### 5.1 图层顺序

```
桌面背景  →  z=0 窗口  →  z=1  →  z=2  →  z=3  →  HUD（最上）
```

同一 `(x,y)` 命中多个窗口时，取 `z` 最大者；`z` 相同取 `win_id` 小者。

### 5.2 窗口绘制规则

```
if (x >= gx) && (x < gx + w) && (y >= gy) && (y < gy + h):
    局部坐标 lx = x - gx, ly = y - gy
    if lx < 2 或 lx >= w-2 或 ly < 2 或 ly >= h-2:  边框（颜色按 owner/selected）
    elif ly < TITLE_H (14):                          标题栏（深灰 + 标题字模）
    else:                                             内容图案 src(lx, ly - TITLE_H, anim_step)
```

- 边框 2 px，**不许用 `<=`**：所有区间一律 `>=` 且 `<`，接缝处才不会出现 1 px 叠画或漏画
- 内容图案只依赖**窗口局部坐标**与 `anim_step`（`anim_step = frame_cnt >> 6`，约 4 Hz），
  保证两节点对同一窗口算出**逐位相同**的像素

### 5.3 HUD（每节点各自的屏）

| 位置 | 内容 | 说明 |
|---|---|---|
| 左上 (8,8) | `A` / `B` | 节点号，颜色 = owner 色 |
| 左下 (8,452) | `OWN A` / `OWN B` | 选中窗口的 owner |
| 左下 (8,468) | `GX 0600` | 选中窗口的全局 x（4 位十进制？第一版用 4 位十六进制更省） |
| 右下 | `LINK OK` / `LINK LOST` | 心跳超时（>6 帧未收到 STATE） |
| 右下第二行 | `SYNC` | genlock 状态（B 是否锁定 A 的帧同步） |

> HUD 用 8×8 字模，字符集 = 数字 + 大写字母 + `-.:/ `，由 `tools/gen_font.py` 生成 ROM。

## 6. 帧同步（genlock）

- A 在自己的帧起始（vblank 第一拍）拉高 `link_sync` 一个 link_clk
- B 收到 `link_sync` 后：
  - 若当前在 vblank 内 → **重置自己的 raster 计数器**，与 A 逐帧对齐
  - 若不在 vblank（漂移超过 vblank 宽度，约 0.5 ms）→ 本帧不处理，下一个 vblank 再对齐（避免画面撕裂）
- 表快照一律在 **raster 帧起始**应用（A 用本地快照，B 用最近收到的 `STATE`）
- 抖动指标：两屏帧号对比，目标 ≤1 行；未锁定（`SYNC` 灭）时仍能正常显示，只是跨接缝在拖动瞬间可能有 1 px 瞬态

## 7. 降级

| 故障 | A 行为 | B 行为 |
|---|---|---|
| 排线断 | 继续显示，HUD `LINK LOST`，`flags.frozen=1` | 冻结最后一张表，继续显示自己那半，HUD `LINK LOST` |
| 恢复 | 继续发 `STATE` | ≤3 帧内重新应用新表 |
| B 掉电 | A 正常，B 半屏无显示 | — |
| A 掉电 | — | B 收不到 `STATE`，冻结（`N=1` 单屏降级在 v1.1 做：所有窗口按 640 宽重新夹取） |

## 8. 按键

| 键 | 功能 | 备注 |
|---|---|---|
| KEY1 | 选中下一个窗口（循环 0→3） | 每次按下 1 个事件，去抖 5 ms |
| KEY2 | 进入/退出拖拽 | 进入时 `flags.dragging=1`；退出时按中心判定 owner |
| KEY3 | 左移 1 px（按住 30 Hz 连发） | 拖拽中才生效 |
| KEY4 | 右移 1 px | 同上 |
| SW1 | 显示接缝标尺（3 px 竖线 + 数字） | 调试用，默认关 |
| SW2 | 冻结所有窗口（拍照对比用） | 验收"0 像素"时用 |

**owner 判定**（KEY2 松开时，由 A 执行）：

```
center = gx + w/2
center <  640  → owner = A
center >= 640  → owner = B
```

窗口跨越接缝但中心在 A 侧时，仍归 A 控制——**避免"窗口一半在 B 屏，人却在 A 板按键"的操作混乱**。

| raster + genlock | ~0.2K | 0 | |
