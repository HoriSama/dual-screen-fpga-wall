# C10 —— 底部滚动字幕（中文 16×16，长按 KEY2 开关）

> 2026-10-31 19:5x 实现 · 已在**仿真**全部验证 · **烧板与配置 Flash 因 USB 掉线待补**（见文末）

## 1. 需求与取舍

操作员要求：屏幕底部加一条滚动字幕，用"长按控制 UI 的那个键"开关。
实际落地：

| 决定 | 取值 | 理由 |
|---|---|---|
| 语言 | **中文 16×16** | 8×8 的中文字不可读；现有 `wall_font_rom` 只有大写 ASCII（41 字） |
| 文本 | `因设备调试问题，今日博物馆暂停营业，`（18 字） | 操作员指定 |
| 位置 | 世界 y = **452..479**（28 行条），字形占 456..471 | 底部整条，跨接缝连续 |
| 速度 | **1 px/帧 = 60 px/s**（3.75 字/秒） | 常见 LED 通知牌的节奏 |
| 开关 | VIEW 模式 **KEY2 长按 ≥1 s** | 短按仍是 UI 显隐；两个功能一个键，靠时长区分 |
| 相册模式 | **不显示**（`wall_scene` 里 `m_on && !album_now`） | 相册是干净的 1:1 照片 |

## 2. 关键设计：相位必须由 A 广播

字幕横跨 1280 px，左半由 A 画、右半由 B 画。**两片的滚动相位只要差 1 px，16 px 的字就会在
接缝处被撕成两半** —— 和"窗口表必须整份广播"是同一个道理。所以：

- 相位是 **9 bit**（512 px 一个周期，32 个 16 px 字格）；
- A：`phase = frame_cnt[8:0]`；
- B：`phase = {copy_mp8, b_seq}`，其中 `b_seq` 是 STATE 帧 byte0 已经广播的
  `frame_cnt[7:0]`，`copy_mp8` 是我新塞进 **byte4 bit7**（原来恒 0）的那一位。
- 于是**负载长度没变**（还是 40 B），旧协议一字没动，只在两个空位里各放一位。

字符串按 **32 字格**排布（18 字 + 14 个空格 = 512 px），所以循环是**无缝**的：
`(x - phase) mod 512` 就是一个 9 bit 减法，字符号 = 结果的高 5 位，格内像素 = 低 4 位。
不需要任何取模逻辑。

## 5. 资源与时序（构建 `20261031_202257_A` / `202522_B`，0 违例）

| | LUT | reg | BRAM | 25 MHz | 150 MHz |
|---|---|---|---|---|---|
| A | **13684 / 19600（69.82%）** | 8262 | 31 / 64 | **+0.267** | **+0.129** |
| B | **9362 / 19600（47.77%）** | 6193 | 31 / 64 | **+0.273** | +0.633 |

相比 C9-R3（A 13370 / B 8993）：A 多 **+345 LUT**、B 多 **+369 LUT** —— 就是 16×16 字模的
case ROM + 位选择 + 比较器。

⚠ **> 中间那一版（`20261031_195352_A`）把**局部 x** 喂给了字幕，A 的 150 MHz 只有 **+0.011 ns**；改成世界坐标后是 **+0.129 ns** —— 同一个功能、不同的接线，TD 布局能差 0.12 ns。字幕逻辑全在 25 MHz 域，这条数字就是纯布局噪声，**每次重建都要先看它**。

## 6. 操作与手感

- VIEW 模式（SW1 下）：**短按 KEY2** = 整体 UI 显隐（松手才响应，比原来晚 ~100 ms）；
  **长按 KEY2 ≥1 s** = 字幕开关（按住 1 s 时立即生效，松手不会再切 UI）；
- 字幕只在桌面模式出现；进相册（SW4 上）自动隐藏，退出相册后按原状态恢复；
- 字幕打开时底条会盖住窗口最下面 28 行 —— 这是设计意图（通知牌压在最上层）。

## 7. 烧板（2026-10-31 20:1x 已完成）

2026-10-31 19:5x 第一次准备烧板时，**两块板的 USB 全部掉线**（拔插/重上电后恢复，端口从 COM7/COM8 变成 **COM7/COM9**）：
`COM7/COM8` 和两个 `Anlogic usb cable v0.1` 都变成 PHANTOM，只剩 `COM9`（其中 B 板，
还跑着旧 bit），`sc query CYUSB` = STOPPED（0x1F 设备未连接），`download` 报
`PRG-9505 USB device open error`。

按 `docs/10` 的教训：**先给板子断电重上电 / 拔插 USB，别改 Windows 安全设置**（这次就是这个办法解决的）。

**20:1x 恢复后完成**：先只烧 A 板（cable 0）并读串口确认它仍是 `node=A` —— 这一步是**校准 cable 编号**
（重新枚举后编号可能变，烧反了两块板会都变成同一节点）；确认无误后烧 B（cable 1），再跑
`persist_pair.ps1`，两片都 `PROG/VERIFY/REFRESH OK`，`refresh` 后 `node=A` / `node=B` 各自正确。
两片现在跑的就是带字幕的 C10 版，配置 Flash 也是。

> ⚠ **字幕默认是关的**：上电后要先在 VIEW 模式（SW1 下拨）**长按 KEY2 约 1 秒**才会出现，
> 短按只切 UI。看不到字幕先确认这一步，而不是怀疑没烧上。
>
> 下面是当初写的恢复步骤，留作下次 USB 再掉时的参考：

```powershell
# 1) 先确认两块板都在、且哪块是 A（有卡）
powershell -ExecutionPolicy Bypass -File tools\probe_flash.ps1 -Ports COMx,COMy
# 2) 烧 JTAG + 写配置 Flash（cable 0 = A / 1 = B）
powershell -ExecutionPolicy Bypass -File tools\probe_flash.ps1 -Flash
powershell -ExecutionPolicy Bypass -File tools\persist_pair.ps1
```

⚠ 现在两片配置 Flash 里存的还是 **C9-R3** 的 bit（没有字幕）；不重跑 `persist_pair.ps1`
的话，一掉电就回到没有字幕的版本。

## 8. 上板后发现的 bug：字幕被喂了"局部 x"（20:2x 修复）

第一次烧上板后，操作员报"**两块屏各自在放自己的字幕**"，不是一条连续的字幕。

**根因**：`wall_scene` 里的 `x` 是**本屏局部坐标**（0..639），世界坐标是
`wx = NODE_X0[11:0] + x`。我把 `wall_marquee` 的 `.x()` 接在了 `x` 上，于是两片都从
world 0 开始画 → 各自放一份。修法是把 `wx` 一路带进 `wall_hud`，只给字幕用：
`wall_marquee .x(wx[10:0])`。HUD 自己的字幕仍然用局部 `x`（它本来就是在两屏上各画一遍）。

**为什么仿真没抓到**：`tb_marquee` 是直接给 `wall_marquee` 喂世界坐标的，模块本身没错，
错在**接线**。所以给 `tb_marquee` 补了一段**接线检查**：拿一个 `wall_hud` 实例，喂
`x=5`（局部）与 `wx=700`（世界），断言底条像素等于 `wall_marquee` 在**世界 700** 的输出。
并且做了**负控**：把 `.x(wx)` 改回 `.x(x)` 时，这段检查立刻报
`WIRING MISMATCH y=457 wx=700: hud rgb=ffd24a marquee rgb=101820` —— 证明它真的能抓到这个 bug。

**教训**（和 C8 的"行起点要按首像素前 N 拍算"是同一类）：跨接缝的东西，一定要确认自己用的
是**世界坐标**，不是本节点的局部坐标；仿真里"模块单独测都对"不等于"接对了"。

## 9. 上板后发现的第二个 bug：计时器从 40 分开始（20:4x→21:2x 修复）

操作员报"计时器一开始就是 40 40，而不是 00 00"。

### 9.1 先量，不要猜

给状态帧加了两字节回读（**byte15 = 秒、byte18 = 分**，BCD；原来这两字节是
`pll_rst_cnt` 和 `rst_cnt`，都近乎恒值），`tools/read_status.ps1` 会打印成
`wallclock : TIME mm:ss`。一量就清楚：

- **走时是对的**：10 秒真实时间前进 11 秒（含读串口的延迟），即 60 帧/秒，没有跑飞；
- **起点不对**：刚烧完就显示 `41:28`，而那正是**板上电 41 分钟**——计数器没被清零。

### 9.2 根因：整个逻辑面从来没有上电复位过

```verilog
reg [23:0] por = 24'd0;
always @(posedge clk50) if (!por[POR_BITS]) por <= por + 24'd1;
wire por_done = por[POR_BITS];
wire por_rst  = !por_done;          // 旧写法
```

`por_done` 完全取决于这 24 位计数器上电时 `por[23]` 是不是 0。这个流程**不给寄存器出初始值**，
一旦它上电就是 1，`por_rst` 永远为 0 → **`logic_rst` 一次都不发** → 时钟、`frame_cnt`、
窗口表……全都从残值开始（只是窗口表随后被按键写成了正常样子，所以一直没被发现）。

### 9.3 三层修法（都做了，从软到硬）

1. `wall_clock` 改成**整寄存器**赋值（`sec_nxt`/`min_nxt` 先算好再整字节打一拍），
   不再对同一个 reg 的两个 nibble 分别做非阻塞赋值；
2. 计数器和 `frame_cnt` 都加**声明初值**（`reg [7:0] sec = 8'h00;`）；
3. **真正的零点**：`clk_rst = logic_rst | (tf_phase != 4'd6)` —— 卡加载器没跑完就一直按住 0。
   加载器 FSM 每次重配都可靠地从头跑（它的状态有确定的初值），所以它的 DONE 是可信的零点。
   代价是计时从"照片加载完成"开始，而这恰好是更合理的语义。B 板不跑加载器、也不画 TIME 行，
   所以它一直停在 00:00，无害。

同时把 `por_rst` 也改成 `!por_done | ~pll_lock`（PLL 未锁定也复位），作为"真·上电复位"的兜底。

### 9.4 验证

烧完 A 后连读三帧：

```
phase=4 (加载中)  wallclock : TIME 00:00
phase=6 (加载完)  wallclock : TIME 01:00     <- 变成 00:01，开始数
+22 s             wallclock : TIME 16:00     <- 秒 = 0x16 = 22 s，走时正确
```

⚠ **状态帧 byte15/byte18 的含义变了**：现在分别是秒/分（BCD），不再是 `pll_rst_cnt`/`rst_cnt`。
`read_status.ps1` 已同步，材料里如果引用过这两个字节要改。

最终构建`20261031_211735_A` / `212015_B`（0 违例）：A LUT 13811（70.46%）、25 MHz **+0.557**、
150 MHz **+0.353**；B LUT 9331（47.61%）、**+0.347 / +0.185**；两片配置 Flash 已重写。
