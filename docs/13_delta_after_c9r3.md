## 可直接引用的数字（全部实测）

**诊断接口**（这块可以当"可观测性"写成亮点）
- 状态帧 **byte 11** = 最近 4 秒（240 帧）里**最差一帧**的"填充未及时完成"行数；
- 状态帧 **byte 19 bits[6:3]** = 被饿死的**窗口掩码**（bit3..0 = w3..w0）；
- `tools/read_status.ps1` 打印 `starved-mask=0100 (w3..w0)` 与 `linebuf: worst frame / 4 s = 13`。

**改前 / 改后**

| | A 板 | B 板 |
|---|---|---|
| 改前（4 秒内最差一帧 / 掩码） | **13 行 / `0100`** | 0 / `0000` |
| 改后（同上） | **0 / `0000`** | 0 / `0000` |

`0100` = **只有 w2（图三）**挨饿 —— 正好对上操作员的"只有图三在 A 屏那条抖"，这是整个故事里最有力的一句。

**算法（一句话可讲清）**
`c1 = min(全宽, (本节点右边界 − gx) + 5)`：源列 `sx = (2·px·zst)>>16`，只要
`zst ≤ 32768`（最多一个源列对一个绘制像素）就有 `sx ≤ px`，所以"本节点能画的像素数 + 5"
就是安全上界；`zst > 32768`（窗口被放大）时不截短。**零乘法器**，只加比较器。

**负载**
A 每行 `192 + 192 + 192 = 576` 字 → `192 + 192 + 45 = 429` 字（**−26%**，跨缝那个 burst **−77%**）。

**回归 / 时序（最新 bit，填表就用这组）**
- 回归 **23 个 TB 全 PASS**（其中新增 `tb_prefetch_node` 钉住列宽上界：A 半屏 `w0=191/w1=191/w2=45/w3=5`，B 两个窗口都 191）；
- 构建 `build/release/20261031_183109_A` / `20261031_183339_B`，**0 违例**：
  A LUT **13370**（68.21%）、reg 8216、**25 MHz +0.153 / 150 MHz +0.304**；
  B LUT **8993**（45.88%）、reg 6184、**+0.242 / +0.127**；
- 权威出处永远是 `build/td_A|B/area.rpt` 与 `final_timing.rpt`。
